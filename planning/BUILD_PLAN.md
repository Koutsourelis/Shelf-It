# Πώς το χτίζουμε

Η λύση περιγράφεται στο [`SOLUTION.md`](SOLUTION.md). Εδώ είναι τι υπάρχει, τι μένει και με ποια σειρά.
Τελευταία ενημέρωση: 14 Νοε, απόγευμα.

## Τι υπάρχει ήδη και τρέχει

Με το ψεύτικο μοντέλο, χωρίς κλειδί (`python scripts/check_setup.py` βγάζει «Όλα εντάξει»):

| Κομμάτι | Πού |
|---|---|
| Ανάγνωση φωτογραφίας σε πίνακα (με πραγματικό μοντέλο στέλνει την εικόνα· δεν έχει δοκιμαστεί) | `read_shelf` στο `agentkit/tools/shelf.py` |
| Σύγκριση με πλανόγραμμα, ποσοστό συμμόρφωσης, σημειωμένη φωτογραφία | `check_planogram` |
| Αναπλήρωση από αποθήκη, κιβώτια προς παραγγελία, πωλήσεις σε κίνδυνο | `replenishment_plan` |
| Προτάσεις διάταξης (χώρος έναντι πωλήσεων, ύψος ματιών) | `layout_suggestions` |
| Παραγγελία στην κεντρική αποθήκη με έγκριση | `order_from_warehouse`, `agentkit/portal.py` |
| Σελίδα κινητού που στέλνει φωτογραφία και ξεκινά τον agent | `/capture`, `console/capture.html` |
| Αυτόματη εκκίνηση όταν πέσει φωτογραφία στο `workspace/photos` | `agentkit/watchers.py` |
| Ρόλος και μέθοδος του agent | `agentkit/scenarios.py` |
| Κατάλογος, πλανόγραμμα, αποθήκη σε CSV | `data/shelf/` |
| Κονσόλα, εγκρίσεις, ίχνος ελέγχου, replay, εγγραφή βίντεο | από τον σκελετό |

## Τι μένει, με σειρά προτεραιότητας

Τα ονόματα μπαίνουν όταν μοιράσουμε τη δουλειά. Κάθε γραμμή είναι ανεξάρτητη από τις άλλες, εκτός αν το γράφει.

| # | Εργασία | Τι θεωρείται «έγινε» | Κάτοχος |
|---|---|---|---|
| 1 | **Τεστ όρασης με πραγματικό μοντέλο.** Κλειδί Gemini στο `.env`, 5 αληθινές φωτογραφίες, `read_shelf` | Ποσοστό σωστών θέσεων γραμμένο στο `DECISIONS.md`. Αν είναι κάτω από ~90%, αλλάζουμε προϊόντα ή prompt πριν από οτιδήποτε άλλο | |
| 2 | **Το ράφι του demo.** Αγορά 9–15 προϊόντων μίας κατηγορίας με καθαρές συσκευασίες, στήσιμο σε 3 επίπεδα, φωτισμός | Φωτογραφίες «σωστό» και «χαλασμένο» ράφι στο `data/shelf/photos/` | |
| 3 | **Αληθινά δεδομένα ραφιού.** Τα CSV του `data/shelf/` με τα προϊόντα που αγοράσαμε (μετά το 2) | `make_demo_data.py` τρέχει, το πλανόγραμμα ταιριάζει με το ράφι | |
| 4 | **Βελτίωση του prompt όρασης** με βάση το τεστ (μετά το 1): φωτογραφίες αναφοράς ανά κωδικό, οδηγίες για ελληνικές ετικέτες | 3 συνεχόμενες σωστές αναγνώσεις του ίδιου ραφιού | |
| 5 | **Κινητό → laptop στο δίκτυο του χώρου.** `HOST=0.0.0.0`, δοκιμή `/capture` από κινητό, εφεδρικά hotspot | Φωτογραφία από κινητό ξεκινά εκτέλεση στην κονσόλα | |
| 6 | **Οθόνη του demo.** Η σημειωμένη φωτογραφία μεγάλη στο κέντρο, πριν και μετά δίπλα δίπλα, λειτουργία παρουσίασης | Διαβάζεται από 5 μέτρα | |
| 7 | **Λίστα εργασιών στο Telegram** με κουμπί «έγινε» που ζητά τη δεύτερη φωτογραφία | Ο υπάλληλος παίρνει τη λίστα στο κινητό | |
| 8 | **Λειτουργία χωρίς πλανόγραμμα** για φωτογραφία αληθινού ραφιού | Ο agent αναφέρει κενά και λέει τι του λείπει για τα υπόλοιπα | |
| 9 | **Εργαλεία χορηγών**, μόνο αν μπαίνουν φυσικά: Iris για προτεραιότητα ευρημάτων, treg για τάσεις, fal για ταμπελάκι | Απόφαση στο `DECISIONS.md` πριν γραφτεί κώδικας | |
| 10 | **Pitch:** διαφάνειες, σενάριο 3 λεπτών, βίντεο, README | Τα αρχεία του `pitch/` χωρίς κενά | |

Οι εργασίες 1 και 2 είναι οι μόνες που μπορούν να ανατρέψουν το σχέδιο. Ξεκινούν πρώτες και παράλληλα.

## Κανόνες δουλειάς στο repo

- Μικρά commits κατευθείαν στο `main`. Πριν από κάθε push: `git pull --rebase`.
- Κάθε άτομο δουλεύει σε δικά του αρχεία όσο γίνεται.
- Το `.env` δεν ανεβαίνει ποτέ. Τα κλειδιά μοιράζονται προφορικά ή από κινητό, όχι σε chat της ομάδας.
- Μόνο συνθετικά, δημόσια ή δικά μας δεδομένα στο repo και στο demo. Ποτέ δεδομένα εργοδότη.
- Το μοντέλο διαβάζει· κάθε αριθμός βγαίνει από κώδικα και γράφεται στο ίχνος ελέγχου.
- Ό,τι υπάρχει μέχρι την ετικέτα `boilerplate` είναι προετοιμασία και δηλώνεται στο README.

## Τι κόβουμε πρώτο αν δεν προλαβαίνουμε

1. Εργαλεία χορηγών (εργασία 9).
2. Λειτουργία χωρίς πλανόγραμμα (εργασία 8).
3. Telegram (η λίστα εργασιών μένει στην κονσόλα).
4. Προτάσεις διάταξης στο demo (μένουν στο «τι ακολουθεί»).

Δεν κόβεται ποτέ: φωτογραφία → ευρήματα → αναπλήρωση → δεύτερη φωτογραφία, το ίχνος ελέγχου, το βίντεο, το replay.
